# Design extraction

Identify actors, responsibilities, boundaries, stores and communication from the supplied document. Preserve its terminology. Cite section headings or short excerpts; label these claims `proposed`. For missing connections, use `inferred` with the reasoning and uncertainty rather than silently adding infrastructure.

When both code and design exist, create separate views if they disagree. State discrepancies in view notes. Use `observed` only for claims supported by inspected implementation.
